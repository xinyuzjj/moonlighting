Moonlighting

你把号建好，AI agent 替你管。
一个桌面 = 一个平台 = 一个账号。agent 在属于自己的隐藏 Windows 桌面里登录、操作、切换标签页， 账号密码存在该桌面独立的凭据库里，永远不进模型上下文。
邮箱也可以交给它——用它去各平台把号申请下来，验证码自己收、自己填。

GitHub 仓库 pip install moonlighting ☕ 支持本项目

它解决什么

让 agent 操作浏览器，通常死在三个地方。

找元素

截图猜坐标，差 11px 就点空。这里读一次无障碍树，按 [ref=e42] 精确点击，还能按可访问名回退定位。

丢状态

每次都是全新 profile，登录态归零。每个桌面一个持久 profile，关掉重开还是登录状态。

传密码

把密码贴进 prompt。这里你在掩码窗里输入，DPAPI 加密存在本地，代理注入，模型只拿到长度。

一个号一个桌面

账号的边界就是桌面名：独立 profile、独立凭据库、独立端口，互不串味。

┌─ 你的桌面 ─────────────────────────────────┐ │ Hermes / Claude / Codex / 任何 MCP 客户端 │ └───────────────┬────────────────────────────┘ │ MCP (stdio) 或 本地 HTTP ┌───────────────▼────────────────────────────┐ │ 隐藏桌面 "junjunni" │ │ ┌──────────────────────────────────────┐ │ │ │ 真实 Chrome / Edge + 持久化 profile │ │ │ │ 标签 0：邮箱 标签 1：平台后台 │ │ │ └──────────────────────────────────────┘ │ │ 凭据代理（DPAPI · 绑定 origin · 有审计） │ └─────────────────────────────────────────────┘

同一个浏览器，多个标签

agent 用 /tabs、/tab?i=1、/newtab?url= 在邮箱和平台后台之间切换， 验证码在这个桌面内部就能取到，不需要跨机器。

账号台账

accounts.py 记下哪套桌面是哪个平台的哪个号、允许做哪些操作。 只存元数据，不存密码。

三行跑起来

Windows 10/11 · Python 3.10+ · Node 18+ · Chrome 或 Edge（系统自带 Edge 即可）

# 安装
pip install moonlighting
moonlighting-setup --home "D:\moonlighting"
moonlighting

# 打印出来的画面地址，直接在上面点也行
preview: http://127.0.0.1:8765/ctl

# 接进任意 MCP 客户端：一行，无路径
{ "mcpServers": { "browser": { "command": "moonlighting-mcp" } } }

现在能做什么

绿色是实测通过的，黄色是零件齐了但还没串成流水线。

能力状态
一个桌面一个浏览器实例，多套并存互不干扰可用
多标签开新页、按索引切换，快照跟随活动标签可用
按无障碍树 ref 填表、点击、导航、滚动、下拉可用
密码不进模型上下文，凭据按桌面隔离可用
掉登录重开还在（持久 profile）可用
实时画面，人可以直接接管可用
账号台账（desktop → 平台 → 账号 → 权限）可用
注册流水线（填表 → 收邮件 → 回填验证码）零件齐，未串成脚本
登录态体检（cookie 过期提醒）未做
人机验证 / 短信验证不绕，交给人

安全模型

密码不进上下文

掩码窗输入 → Windows DPAPI 加密 → 绑定 origin → 代理注入。工具只返回 {ok, verified, id_len, pwd_len}。

每次注入都有审计

时间、动作、origin、handle、结果码写进 audit.jsonl，从不记录明文。

危险动作要人确认

ask_user 不带 --yes 一律阻塞；forbid 硬拦越界动作。

不绕人机识别

驱动的是真实浏览器，不改指纹、不打码、不硬闯风控。遇到验证码就停下来交给你。
