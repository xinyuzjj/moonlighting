01

它解决什么

让 agent 操作浏览器，通常死在三个地方。

找元素

截图猜坐标，差 11px 就点空。这里读一次无障碍树，按 [ref=e42] 精确点击，还能按可访问名回退。

丢状态

每次都是全新 profile，登录态归零。每个桌面一个持久 profile，关掉重开还在。

传密码

把密码贴进 prompt。这里你在掩码窗输入，DPAPI 加密存在本地，代理注入，模型只拿到长度。

02

一个号一个桌面

账号的边界是桌面：一个目标账号一个桌面、一套 profile、一套凭据库。邮箱账号放在同一个桌面的另一个标签页里，所以在里面就能收发验证码。

同一个浏览器，多个标签

邮箱在标签 0，平台后台在标签 1，agent 在同一个桌面里来回切，验证码当场就能读，不需要跨机器。

账号台账

accounts.py 记下哪套桌面是哪个平台的哪个号、允许做哪些操作。只存元数据，不存密码。

05

安全模型

假设模型会犯错、也会被诱导——所以关键动作不交给它决定。

密码不进上下文

掩码窗输入 → Windows DPAPI 加密 → 绑定 origin → 代理注入。工具只返回 {ok, verified, id_len, pwd_len}。

每次注入都有审计

时间、动作、origin、handle、结果码写进 audit.jsonl，从不记录明文。

危险动作要人确认

ask_user 不带 --yes 一律阻塞；forbid 硬拦越界动作。

不绕人机识别

驱动的是真实浏览器，不改指纹、不打码、不硬闯风控。遇到验证码就停下来交给你。
